# ADR-0001：用 RRF 多通道融合替代线性加权排序

- 状态：已采纳
- 日期：2026-11-05
- 相关模块：`com.scenemind.core.ranking`、`VideoEvidenceRetrievalService`

## 背景

视频证据检索有三条独立通道：语义（向量相似度）、词法（转写关键词命中率）、视觉（OCR 关键词命中率）。
改造前的排序把它们直接线性相加：

```
score = 0.6 * semantic + 0.25 * lexical + 0.15 * visual
```

三个问题：

1. **量纲不一致**：`semantic` 可能来自 Qdrant（`[0,1]` 的相似度）或本地 cosine（`[-1,1]`），
   而 `lexical` / `visual` 是 `[0,1]` 的命中率。换打分尺度就等价于偷偷改了权重。
2. **权重不可解释**：0.6 / 0.25 / 0.15 无法从数据推出来，也无法按视频类型调整。
3. **固定 TopK 不适配长视频**：数小时视频里相关证据分散，固定取前 3 个 chunk 后展开全部
   segment，结果容易集中在同一段时间；相邻 ASR 切片还会重复占据名额。

## 备选方案

| 方案 | 优点 | 否决原因 |
| --- | --- | --- |
| 保留加权求和，只调权重 | 改动最小 | 没解决量纲问题，换向量服务仍会漂移 |
| 分数归一化（min-max / z-score）后再加权 | 直观 | min-max 依赖当前候选集极值，同一片段跨查询分数不稳定；z-score 需估均值方差，候选数少时不可靠；且远程分与本地分不是同一分布 |
| Learning-to-rank | 理论上限高 | 缺真实标注数据与在线特征服务，结果不可解释、不可离线回放 |
| **RRF（Reciprocal Rank Fusion）** | 只用序关系、零训练、可解释、可确定性回放 | 丢失分数绝对强度（见「后果」） |

## 决策

1. 三通道各自独立产出**有序列表**，融合只使用名次：

   ```
   score(d) = Σ_c  w_c / (k + rank_c(d)),  k = 60（可配）
   ```

   原始分数永不进入同一个加法式。权重只缩放「秩」，不缩放分数。
2. 融合（`fuse`）与选择（`select`）拆成两步，中间由 `TopKPolicy` 决定预算。
3. 选择阶段两轮贪心：第一轮每个时间窗只取一条保证覆盖，第二轮补满名额；
   时间相邻且文本 bigram 相似度超阈值的片段判近重复并抑制。
4. 参数全部外部化到 `scenemind.ranking.*`，A/B 不需要改代码。
5. 保留 `LinearBaselineRanker` 复现旧公式，作为离线评测的对照组。

## 后果

**正面**

- 对分数的任意**单调变换**免疫：评测里把语义分数做 `37x + 5` 后，RRF 的 TopK 集合
  Jaccard 为 1.000，线性加权掉到 0.500。
- 冗余率 0.143 → 0.000；每次检索有可解释诊断（通道名次、选中阶段、抑制数、覆盖窗数）。
- 排序内核变成纯函数，可脱离 Spring / Docker / LLM 做单元测试与回放。

**负面 / 已知取舍**

- RRF 丢掉分数绝对强度，「所有证据都很弱」这个信号没了 → 在 `TopKPolicy` 里用
  「命中通道数」补回置信度，并保留 `retrievalTopScore` 埋点。
- 固定时间窗存在硬边界，跨窗的同一话题可能被分到两个窗 → 窗口宽度参数化。
- 并列同分必须稳定 tie-break（按 `startMs` + `id`），否则评测不可复现。
- **本合成数据集上 Recall@8 与时间覆盖率持平（1.000）**：改造证明的是冗余与鲁棒性收益，
  不是召回上限。验证召回收益需要真实标注集（路线图第一项）。

## 后续修正：通道隔离

RRF 实现上线后发现一个语义漏洞：融合时每个通道都拿到同一份**全量候选**，于是「没有 OCR 证据的片段」照样能在视觉通道拿到名次。

- 后果一：`matchedChannels` 恒为 3，「所有证据都很弱」这个信号失真；
- 后果二：`TopKPolicy` 的「仅命中单一通道 → 扩召回」分支永远不可达，弱证据扩召回实际上从未生效。

修复要同时改两层：

1. 内核 `HybridRanker.fuse()`：按 `channelsPresent` 过滤，只有声明了该通道的候选才参与该通道排名；`channelsPresent` 全为空视为「未标注的旧数据」，保持原行为以兼容历史调用方；
2. 适配层 `VideoEvidenceRetrievalService`：构造三个 `ChannelRanking` 时按通道过滤，不再把同一份候选交给三个通道。

`HybridRankerTest` 增加了通道隔离用例；离线评测走同一条 `fuse → TopKPolicy.decide → select` 链路，所以报告能反映这次修复。

## 验证

- `HybridRankerTest`：单调缩放不变性、通道隔离、去冗余、跨时间窗覆盖、零权重通道、外部预算、非法配置。
- `OfflineEvaluatorTest`：RRF 稳定性恒为 1.0、线性加权 < 1.0、四项指标不退化、评测完全确定。
- `bash scripts/run-benchmark.sh` → `docs/benchmark-report.md`，12 条自检断言，CI 做报告 diff 门禁。
