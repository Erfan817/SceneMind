## T1｜为什么把线性加权换成 RRF（**主推话题**）

**钩子**：「我发现换个向量服务，检索排序就会悄悄变，根源是三种不同量纲的分数被放进了同一个加法式。」

**技术骨架**

- 改造前：`score = 0.6*semantic + 0.25*lexical + 0.15*visual`。`semantic` 可能是 Qdrant 的 `[0,1]`，也可能是本地 cosine 的 `[-1,1]`；`lexical` / `visual` 是关键词命中率 `[0,1]`。
- 改造后：每个通道独立产出有序列表，融合只用名次：

  ```
  score(d) = Σ_c  w_c / (k + rank_c(d))        k = 60（可配）
  ```

  权重只缩放「秩」，不缩放原始分数，因此通道之间不需要任何分布假设。
- 评测里的量化证据：把语义分数做 `37x + 5` 的单调变换后，线性加权的 TopK 集合 Jaccard 掉到 **0.500**，RRF 保持 **1.000**。

**可能追问**

| 追问 | 回答要点 |
| --- | --- |
| 归一化（min-max / z-score）不也能解决？ | min-max 依赖**当前候选集**的极值，同一片段在不同查询下分数会变；z-score 要估均值方差，长视频片段数少时不稳定；远程向量分和本地 cosine 本来就不是同一分布。RRF 只用序关系，是最省假设的做法。 |
| `k=60` 怎么来的？ | RRF 原始论文（Cormack et al., 2009）的经验值，用来抑制头部名次过度主导。`k` 越大，各名次贡献越接近。我把它和通道权重都做成配置项，可以用评测集 A/B，而不是拍死在代码里。 |
| RRF 的缺点？ | **丢掉了分数的绝对强度**——「所有证据都很弱」这个信号没了。我在 `TopKPolicy` 里用「命中通道数」把置信度补回来，并输出 `retrievalTopScore` 埋点。另外并列同分必须稳定 tie-break，我用 `startMs + id` 保证结果确定，否则评测不可复现。 |
| 为什么不上 learning-to-rank？ | 需要真实标注数据和在线特征服务，这个项目没有。RRF 零训练、可解释、可离线回放，是合适的基线；路线图里写了「接入真实标注集后再考虑升级」。 |

**容易翻车**：别把 RRF 说成「效果一定更好」。它解决的是**量纲鲁棒性**，不是召回上限；这份数据集上 Recall@8 是持平的。

## T2｜为什么把策略层抽成零依赖纯函数内核

**钩子**：「原来的『离线评测』其实还在调 LLM，必须配 API Key、结果还不可复现。我把排序和校验抽出来，现在一个 JDK 就能跑完整评测。」

**技术骨架**

- `com.scenemind.core.{ranking,evidence,eval}` 不 import 任何 Spring / 数据库 / 网络类；`server` 只做三件事：DTO 适配、外部依赖降级、埋点。
- `HybridRanker` 拆成 `fuse()`（全量融合排序）与 `select()`（按预算选择）两步，中间可以插入 `TopKPolicy` 动态决策。
- 验证零依赖的方式很直接：`javac --release 21` 单独编译 `core/` 目录成功，`scripts/run-benchmark.sh` 就是这么做的。

**可能追问**

| 追问 | 回答要点 |
| --- | --- |
| 为什么不拆成独立 Maven 模块？ | 独立模块要引入 reactor 聚合、改父 POM 与 CI 构建顺序，对一个已有工程是较大的结构性改动；收益（物理隔离）不如风险。包级隔离 + 单编译验证已经达到「可独立编译运行」的目标。 |
| 纯函数怎么处理降级和日志？ | 刻意不处理。降级、重试、埋点全部留在适配层，内核只做确定性计算。这样同一份输入永远同一份输出，才能做回放和 A/B。 |
| 怎么保证重构没改坏原行为？ | `EvidenceVerificationService` 三个 public 方法签名和语义不变，原有 4 个回归测试**零修改**通过；后端总共 20 个测试类全绿。 |

**容易翻车**：不要说「完全重写了架构」。这是**分层重构**，基础设施层一行没动。

## T3｜长视频特有的两个检索问题：跨时段覆盖与近重复

**钩子**：「数小时视频里，TopK 很容易全挤在同一段——因为 ASR 每 60 秒切一片，相邻片段说的是同一句话。」

**技术骨架**

- **两轮贪心选择**：第一轮每个 5 分钟时间窗只取融合分最高的一条；名额不足时，第二轮放宽「每窗一条」按融合分补满。结果里每个元素都带 `selectionPass`，可解释。
- **近重复抑制**：需同时满足「时间中点距离 < windowMs」**且**「中文字符 bigram Jaccard ≥ 阈值」才判冗余。用 bigram 是因为中文免分词，且对 OCR 的空格、标点、全半角噪声鲁棒（归一化时只保留字母数字）。
- **复杂度**：`fuse` 是 O(C·N log N)（C=3 通道），`select` 最坏 O(K·N)；数小时视频的片段数 N 在几百量级，K ≤ 12，完全可接受。
- 结果：证据冗余率 0.143 → 0.000，评测报告里能看到「抑制近重复片段 4 条」。

**可能追问**

| 追问 | 回答要点 |
| --- | --- |
| 固定 5 分钟窗口合理吗？ | 与片段摘要粒度对齐。对短视频可以调 `scenemind.ranking.window-ms`。硬边界会把跨窗的同一话题切到两个窗，这是已知取舍，参数化了以后可以按视频类型调。 |
| 会不会误删真正不同的证据？ | 双条件 AND，且阈值可配；诊断里记录抑制数量和覆盖窗数，可回放检查。评测集里专门构造了「同窗重复」和「不同时段独立内容」两类样本。 |
| 为什么不用 MMR？ | MMR 需要逐条算与已选集合的相关度并调 λ，在只有几十条候选时收益有限；「每窗一条」更贴合长视频的时间结构，也更容易向非算法同事解释。 |

## T4｜自适应召回预算与成本治理

**钩子**：「固定 `TOP_K=3` 两头不讨好：证据充足时硬塞不相干片段，证据稀疏时又递不到足够上下文；而证据条数直接决定 prompt 长度和 Token 成本。」

**技术骨架**

`TopKPolicy.decide(fused, requestedK)` 三条规则，按优先级：

1. 头部只命中 1 个通道 → 证据弱，`EXPAND`（+2，上限 clamp）；
2. 截断处出现分数平台（第 k 与 k+1 名相对差 < 8%）→ 说明同质量片段被切开，`EXPAND`（+1）；
3. 头部三通道齐中且领先 second ≥ 50% → `SHRINK`（−2，下限 clamp）；
4. 否则 `KEEP`。决策带人类可读理由，写进 debug 日志与埋点。

**可能追问**

| 追问 | 回答要点 |
| --- | --- |
| 阈值是不是拍脑袋？ | 是启发式，我不回避。参数全部外部化，下一步就是用评测集做参数寻优（已列路线图）。在没有标注数据前，可解释的规则比不可验证的「智能」更合适。 |
| 会不会来回振荡？ | 无状态、单次决策、有 min/max clamp，不存在反馈回路。 |
| 和成本护栏怎么配合？ | 检索层控制进 prompt 的证据条数；上层还有用户级/全局令牌桶、有限次指数退避、AgentLoop 两轮上限，形成多层约束。 |

## T5｜一个真实的假阳性 Bug：ASR + OCR 跨通道拼接（**最有亮点**）

**钩子**：「模型可以从语音的尾巴和画面的开头，拼出一句视频里根本不存在的话，而旧校验会判定『有证据』。」

**复现**

```
segment 60–120s
  ASR：我们计划八月一日正式上线。
  OCR：正式上线：8月3日
旧实现把两者拼成 → "我们计划八月一日正式上线。 正式上线：8月3日"
模型给出 evidence.content = "上线。正式上线"
归一化后 "上线正式上线" 是拼接串的连续子串 → 校验通过 ✗
但这句话在 ASR 里不存在，在 OCR 里也不存在。
```

**修复**

- `ASR+OCR` 不再拼成一个串：分别检查两条通道，**要求证据在同一通道内完整命中**；
- 只在拼接串里能命中的，判为 `CROSS_CHANNEL_SPLICE` 并拒绝；
- 通过条件维持「归一化后连续子串命中」，不放宽，保证原有回归不破；
- 归一化：全角转半角、只保留字母数字、统一大小写。

**可能追问**

| 追问 | 回答要点 |
| --- | --- |
| 模型只是改写了原文怎么办？ | 仍然拒绝（避免放宽后放进幻觉），但 `AuditResult.similarity()` 会给出二元组覆盖率；接近 1 说明是「改写」，接近 0 说明是「编造」。这给后续放宽策略提供数据，而不是直接拍板。 |
| 9 类拒绝原因怎么用的？ | 带 `retryable` 标记：时间戳越界 / 通道为空 / 文本未找到 → 回检索定向补证据；来源造假 / 跨通道拼接 → 直接判幻觉，不再烧一轮 Token。**当前只做到判定与输出，接进 AgentLoop 的重试策略是路线图**，别说过已完成。 |
| 音画冲突怎么检测？ | 正则抽中/阿数字日期，中文数字转阿拉伯归一化为 `M月D日`；ASR 与 OCR 集合都非空且不相交即报冲突。目的是**标注不确定性**，不是替用户选一个答案。 |

## T6｜离线评测与 CI 回归门禁

**钩子**：「改了排序算法，怎么证明没退化？我做成确定性回放，PR 里报告没更新就直接挂。」

**技术骨架**

- 数据集：2 小时合成课程视频，24 个时间窗 / 28 个候选片段 / 4 个标注相关片段，刻意构造三类干扰：跨时段分散、同窗近重复、纯画面证据（语音里没有）。
- 四项指标：`Recall@K`、`TemporalCoverage`（命中的相关时间窗比例）、`RedundancyRate`（TopK 内近重复配对占比）、`RankStability`（分数单调变换后 TopK 集合 Jaccard）。
- 基线 `LinearBaselineRanker` 保留旧公式，A/B 同数据集对比。
- CI：独立 `core-evaluation` job 跑 `scripts/run-benchmark.sh`（零 Docker / 零 LLM），再 `git diff --exit-code -- docs/benchmark-report.md`，保证提交的指标是程序算出来的且没退化。

**可能追问**

| 追问 | 回答要点 |
| --- | --- |
| **为什么 Recall 没有提升？** | 如实说：这份压力集里相关片段信号较强，线性加权也能全召到，所以 Recall@8 持平 1.000。改造解决的是**冗余和量纲鲁棒性**。要验证召回收益必须上真实标注集，这是我在路线图里列的第一项。**别临时编一个提升幅度。** |
| 合成数据集有什么局限？ | 分布单一、没有真实 ASR 错字与查询多样性，只能做**回归门禁**，不能当业务收益的证据。报告里明确写了「非线上真实流量」。 |
| 怎么保证报告不是手填的？ | 报告由 `SceneMindBenchmark` 生成，CI 重算后做字节级 diff；程序自带 8 条断言，失败非零退出。 |
| 为什么不用 JaCoCo 覆盖率门禁？ | 还没接，是已知缺口（路线图）。当前靠「新增 26 个用例 + 原有 14 个测试类零修改通过」保证回归，不谎称覆盖率数字。 |

## T7｜异步任务链路：幂等、Checkpoint、失败恢复（沿用层，但要能讲）

这部分不是我写的，但项目里问到必须答得出来，否则会显得只懂自己那一块。

- **上传**：前端 5MB 分片，Redis 记录已完成分片，MinIO 保存合并文件；弱网中断续传。
- **削峰**：RocketMQ 把解析移出请求线程，提交即返回 202；SSE 推阶段。
- **幂等**：Redisson 按「内容指纹 + 分析目标」加锁，拦截并发与重复消费；先查已有结果与 Checkpoint 再决定是否复用。
- **恢复**：Checkpoint 以 **MySQL 为恢复真源、Redis 为热缓存**，持久化 VideoContext、分块、计划、Critic 状态；失败消息进独立主题与失败任务表，管理接口可重投。
- **追问**：「MySQL 和 Redis 不一致听谁的？」→ MySQL 是真源，Redis 只是加速；「重复消费怎么办？」→ 幂等锁 + 结果复用 + Checkpoint 恢复三层。

## T8｜降级策略与它的代价

- 向量库 / Embedding 不可用 → 退化到本地关键词与已有向量排序，主链路不中断；意图路由不可用 → 回退通用模式。
- **为什么这样设计**：长视频分析已经跑了十几分钟，不能因为一个可降级的基础设施故障让整个任务前功尽弃。
- **代价要讲出来**：降级后结果质量会下降，因此必须有 `vectorStoreFallbacks` / `embeddingFallbacks` / `retrievalIntentFallbacks` 埋点，不然降级会变成静默的质量事故。这是「优雅降级」和「偷偷变差」的区别。

## T9｜如果重做，我会改什么（体现工程成熟度）

1. 接真实标注视频集，验证召回收益而不只是鲁棒性；
2. 用评测报告驱动 `k` 与通道权重自动寻优，把启发式阈值换成有依据的参数；
3. 把 `retryable` 拒绝原因真正接进 AgentLoop 的重试策略（目前只做到判定与输出）；
4. 检索诊断落到前端调试面板，支持单次任务 trace 回放；
5. 补 JaCoCo 覆盖率门禁和端到端契约测试。

主动讲「还差什么」比被问出来强。

> 「基础设施层（上传、消息队列、存储、工作台）我基于一个 MIT 协议的长视频分析实现搭起来，这部分不是我原创；检索排序、证据校验、离线评测这三块是我重新设计并实现的，也是我主要想聊的部分。原实现的问题、我的取舍和验证数据都在 README、ADR 和评测报告里。」

坦诚 + 立刻把话题拉回自己真正做过的部分。实习生面试考察的是「能不能读懂并改进已有代码库」，这比「独立写完全栈」更贴近真实工作，也更经得起追问。**不要删许可证署名或声称完全原创**——commit 时间线、包结构演进、中间件选型细节一问就穿帮，诚信问题在筛选里是一票否决。
