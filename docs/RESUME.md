## 版本 A｜一行版（简历「项目经历」标题下 / 个人主页）

> **SceneMind** — 长视频证据可核验 Video Agent（个人项目，Java 21 / Spring Boot 3 / Vue 3）：主导检索与证据层重构，用 RRF 多通道融合 + 结构化证据校验 + 确定性离线评测替代线性加权与布尔校验；合成评测集上量纲稳定性 0.50 → 1.00、证据冗余率 14.3% → 0，新增 26 个单元测试。

## 版本 B｜标准项目经历（推荐，直接粘贴）

**SceneMind｜长视频证据可核验 Video Agent 工作台**　`个人项目`　`2026.09 – 2026.11`

**技术栈**：Java 21、Spring Boot 3.5、MyBatis-Plus、RocketMQ、Redis/Redisson、MySQL、MinIO、Qdrant、Vue 3、FFmpeg、Tesseract、LangChain4j

- **主导检索排序层重构**：发现语义（Qdrant `[0,1]` / 本地 cosine `[-1,1]`）、词法、视觉三路分数量纲不一致导致线性加权 `0.6/0.25/0.15` 排序漂移；改为 RRF 多通道融合 `Σ w/(k+rank)`，并加入 5 分钟时间窗覆盖、中文 bigram 近重复抑制与可解释诊断。离线 A/B 中量纲稳定性 **0.50 → 1.00**、证据冗余率 **14.3% → 0**。
- **设计零依赖纯函数内核**：把排序与证据校验从 Spring Service 抽离为 `core.ranking` / `core.evidence`，仅用 `javac` 即可编译运行；新增 26 个单元测试覆盖排序不变性、去冗余、拒绝原因与冲突检测，**原有 14 个测试类零修改全部通过**，保证改造不破坏既有语义。
- **修复证据校验假阳性**：将 `supported()` 的布尔判定升级为结构化 `AuditResult`（9 类拒绝原因 + `retryable` 标记）；隔离 ASR / OCR 通道，堵住「语音尾巴 + 画面开头拼接出原文不存在的句子」被判为有效证据的漏洞；新增音画冲突检测，显式标注不确定性。
- **搭建可回归的评测闭环**：实现确定性离线回放（固定数据集、不启动 Spring / 不连数据库 / 不调用 LLM），产出 Recall@K、时间覆盖率、冗余率、量纲稳定性四项指标；评测入口自带 8 条断言，CI 校验提交的报告与生成结果一致，策略变更未更新指标即卡住 PR。
- **工程化收口**：策略参数外部化为 `scenemind.ranking.*` 配置并接入 Spring Bean，支持不改代码做 A/B 调参；实现按通道命中数与分数分布动态调整召回预算的 `TopKPolicy`；包名规范化、补充架构决策记录与可复现评测脚本。

## 版本 D｜面试口述（60 秒）

> 「SceneMind 是一个面向长视频的 Video Agent 工作台，核心目标是让模型给的每条结论都能回到原始视频里被核验。我接手后没有去动上传、消息队列这些基础设施，而是聚焦在决定结果质量的『检索 → 证据 → 评测』链路上。
> 最先发现的问题是检索把三种量纲完全不同的分数直接加权相加，换一家向量服务排序就会漂。我把排序层抽成零依赖的纯函数内核，改成 RRF 多通道融合，再加时间窗覆盖和近重复抑制；证据侧把布尔校验改成带拒绝原因的结构化判定，顺手修掉了一个跨通道拼接导致的假阳性。
> 最有价值的是评测：原来的『离线』评测其实还在调真实 LLM，我改成确定性回放并接进 CI 门禁，现在改了算法没更新指标，PR 会直接挂。整套东西只要一个 JDK 就能复现。」

## 用词边界（重要）

| 可以写 | 不要写 | 原因 |
| --- | --- | --- |
| 「主导检索与证据层重构」「设计并实现 core 策略层」 | 「从零独立设计并开发了整套分布式视频平台」 | 基础设施层是沿用，前者准确、后者可被 commit 历史与代码风格证伪 |
| 「合成评测集上，量纲稳定性 0.50 → 1.00」 | 「线上排序准确率提升 100%」 | 无生产流量，且指标含义不同 |
| 「证据冗余率 14.3% → 0」 | 「召回率大幅提升」 | Recall@8 在本数据集上**持平（1.000）**，如实说明反而加分 |
| 「新增 26 个单测、原有 14 个测试类零修改通过」 | 「测试覆盖率 XX%」 | 未接入覆盖率工具，不要编 |
| 「CI 回归门禁」 | 「落地到生产 / 服务 N 万用户」 | 部署形态是本地单机 |

## 如果面试官问「这是你一个人从零写的吗」

建议直接、简短、不闪躲：

> 「基础设施层（上传、消息队列、存储、工作台）我基于一个 MIT 协议的长视频分析实现搭起来，这部分不是我原创；**检索排序、证据校验、离线评测这三块是我重新设计并实现的**，也是这个项目里我主要想聊的部分。原实现的问题、我的设计取舍和验证数据都在 README 和 ADR 里。」

这个回答在实习面试里是**加分**的：能读懂并改进一个已有企业级代码库，比声称独立写完全栈更可信，也正好体现工程师日常真实工作状态。千万不要删许可证署名或声称完全原创——面试官一问 commit 时间线、包结构演进、某个中间件的选型细节就会穿帮，而诚信问题在实习筛选里是一票否决。
